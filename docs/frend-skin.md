# Frend Skin — своя система скинов для оффлайн-аккаунтов

Документ описывает, как сделать «как в TL»: игрок ставит скин в лаунчере, и этот
скин виден в игре — и ему самому, и другим игрокам с этим лаунчером.

## 1. В чём проблема

Minecraft Java берёт скин не из файла, а с серверов Mojang: клиент спрашивает
«какой скин у игрока с таким UUID». Для **оффлайн-аккаунта** UUID вычисляется из
ника локально, и Mojang о таком игроке ничего не знает — поэтому игра рисует
стандартного Стива или Алекса. Никакой файл, положенный рядом с игрой, на это не
влияет: клиент просто не смотрит на диск.

Значит, чтобы скин появился, нужно **вмешаться в клиент** — подменить ответ
«откуда брать скин». Именно это делают TL и подобные лаунчеры: патчат клиент и
подставляют свой сервер скинов.

## 2. Из чего состоит система

Три независимых части:

| Часть | Что делает | Где живёт |
|---|---|---|
| **A. Лаунчер** | хранит выбранный скин, привязывает его к аккаунту, публикует по HTTP | уже в лаунчере |
| **B. Клиентский источник** | заставляет игру брать скин по нашему адресу | мод/патч в сборке |
| **C. Общий сервер** | отдаёт скины всех игроков по нику | хостинг (нужен для «видеть других») |

Без **B** скин не появится в игре вообще. Без **C** игрок видит только свой скин
(остальные для него — Стивы), потому что чужих скинов у его клиента нет.

## 3. Часть A — лаунчер (сделано)

- Скины лежат в папке скинов лаунчера (`SkinsDir`), их можно импортировать из
  файла, по URL или по нику игрока, и смотреть в 3D.
- Для оффлайн-аккаунта выбранный скин привязывается к нику и сохраняется в
  настройке `FrendSkinBindings` (JSON: `{"ник": {"path": "...", "model": "classic"}}`).
- При запуске лаунчер поднимает локальный HTTP-сервер (`FrendSkinServer`) на
  `http://127.0.0.1:<порт>`:
  - `GET /skin/<ник>.png` — файл скина;
  - `GET /skins.json` — список всех опубликованных скинов;
  - `GET /` — проверка, что сервер жив.
- Порт сохраняется в `FrendSkinPort`, включение — `FrendSkinEnabled`.

Этого достаточно, чтобы скин **был доступен по адресу**. Осталось заставить игру
этот адрес спросить.

## 4. Часть B — клиентский источник (следующий шаг)

Два пути, у каждого своя цена.

### B1. Мод CustomSkinLoader (рекомендую)

- Работает на Fabric, Quilt, Forge, NeoForge — то есть **без Forge тоже**, если
  сборка на Fabric.
- Умеет брать скины из локального файла и с HTTP-сервера.
- Лаунчер может ставить его сам: скачать jar нужной версии с Modrinth, положить в
  `mods/`, сгенерировать конфиг с нашим адресом.
- Ограничение: **ванильная сборка без мод-лоадера** мод не примет. Для таких
  лаунчер может предложить «включить поддержку скинов» — доустановить Fabric в
  эту сборку (лаунчер это уже умеет).

### B2. Патч клиента через javaagent (универсально, но сложнее)

- Лаунчер добавляет в запуск `-javaagent:frendskin.jar`.
- Агент перехватывает в authlib метод, который возвращает текстуры игрока
  (`YggdrasilMinecraftSessionService#getTextures`), и подставляет наш адрес.
- Плюс: работает на **любой** версии и без мод-лоадера.
- Минус: нужно аккуратно патчить байткод (ASM), а сигнатуры классов в разных
  версиях отличаются. Это отдельная большая работа с проверкой на нескольких
  версиях Minecraft.

## 5. Часть C — общий сервер (чтобы видеть других)

Пока сервер локальный, каждый видит только свой скин. Чтобы игроки видели друг
друга, нужен один общий адрес.

Минимальный сервер:

```
GET /skin/<ник>.png        -> PNG скина
GET /skins.json            -> { "ник": {"skin": "...", "model": "classic|slim"} }
PUT /skin/<ник>.png        -> загрузка скина (по токену лаунчера)
```

- Хранилище: папка с файлами + JSON-манифест (хватит и на 10 000 игроков).
- Хостинг: любой VPS или бесплатный вариант (Cloudflare Workers + R2, GitHub
  Pages для статики — если загрузка не нужна).
- Лаунчер получает адрес из настройки `FrendSkinServerUrl` и раздаёт его клиенту.
- Ник — единственный ключ, поэтому на сервере имеет смысл проверять, что игрок
  действительно владеет ником (хотя бы по токену лаунчера).

## 6. Порядок работ

1. **Фаза 1 (готово):** выбор скина в лаунчере, привязка к аккаунту, локальный
   HTTP-сервер скинов.
2. **Фаза 2:** авто-установка CustomSkinLoader в сборки на Fabric/Forge +
   генерация конфига на локальный сервер. Проверка: скин виден в одиночной игре.
3. **Фаза 3:** общий сервер + загрузка скинов из лаунчера, чтобы игроки видели
   друг друга.
4. **Фаза 4 (по желанию):** javaagent-патч для ванильных сборок без мод-лоадера.

## 7. Что важно понимать

- Скин на оффлайн-аккаунте — это всегда компромисс: официальный Minecraft такого
  не умеет, поэтому любые «скины без аккаунта» — это вмешательство в клиент.
- Игроки **без** Frend Skin (и без мода) не увидят наши скины: для них мы
  останемся Стивами. Это ограничение любой самодельной системы скинов, включая TL.
- Скины не влияют на безопасность аккаунта: это только картинка.

00 · Короткий вывод

Что это
Не лаунчер. Нативный загрузчик-обновлятор «GDev Updater» (пакет by.gdev.*), собранный GraalVM Native Image (Substrate VM)

Упакован / обфусцирован
НЕТ ни UPX, ни VMProtect, ни шифрования секций, ни анти-отладки. Энтропия .text = 6.06 — обычный машинный код

Лаунчер внутри
НЕТ в 72 МБ нет ни одного ZIP/JAR. Лаунчер (original-TLauncher-2.9xxx.jar) скачивается из сети

Что делает
гонка зеркал → конфиги → проверка sha1+размер → распаковка → запуск встроенной JRE 21.0.11 с org.tlauncher.tlauncher.rmo.TLauncher

Вредоносное ПО
НЕ НАЙДЕНО но есть телеметрия с HWID, выгрузка логов на сторонние домены, PPI-офферы браузеров, реклама, self-update и одно зеркало по plain HTTP

Модель
Adware-подобная монетизация: партнёрские браузеры + реклама + платные серверы + статистика

Главная мысль. Этот exe сам по себе почти ничего не говорит о конечном поведении: он «тонкий» —
всё интересное живёт в jar'е, который он тянет с сервера и обновляет независимо от exe. Анализировать
надо пару «starter + jar», а не один файл.

2.2. Экспорт и импорт

  702 экспорта: 591 — Java_com_sun_glass_ui_win_* (JavaFX/Glass UI), остальные — graal_*, JNI_*, JNU_*, JNI_OnLoad_glass / _prism_d3d / _javafx_font / _javafx_iio / _net / _nio / _sunmscapi / _zip.
      То есть в образ статически вкомпилированы JDK-модули и JavaFX целиком.

  35 DLL в импорте, ничего экзотического: KERNEL32 / USER32 / ADVAPI32 / WS2_32 / CRYPT32 / ncrypt / Secur32 / IPHLPAPI / WINHTTP / MSVCP140 / VCRUNTIME140 + UIAutomationCore, dwmapi, IMM32, WINMM (это JavaFX/Glass).

  CRYPT32 / ncrypt / Secur32 — это JDK-провайдеры (sun.security.mscapi), а не «своя крипта».

Вывод: распаковывать нечего — код лежит открытым машинным кодом. Проблема тут не «упаковка», а поведение.

04 · Дизайн и интерфейс

Интерфейс — JavaFX 21.0.11 (стекло Glass + рендер Prism/D3D), вкомпилированный прямо в exe. Никакого «нативного Win32-окна»: всё рисует JavaFX, поэтому в импорте и торчат UIAutomationCore, dwmapi, IMM32, WINMM.

4.2. Экраны и контролы

  1Окно обновления ProgressStage / UpdateПрогресс загрузки, скорость, «Downloaded X MB from Y MB», кнопки Update / Skip, чекбокс «не показывать это обновление». Кнопка RoundUpdaterButton — скруглённая, с собственной картинкой.

  2Диалог оффера PointOffer / OwnImageCheckBoxОтдельный экран с картинкой оффера, чекбоксом согласия и двумя кнопками: «Accept offer and Update» / «Decline offer and Update». Обновление предлагается вместе с установкой партнёрского продукта.

  3Баннеры Banner / UpdaterMessageViewРесурсы banner.png, without-banner-offer.png; список баннеров приходит с сервера (banners= в модели), т.е. реклама в окне меняется удалённо.

  4Стартовая страница WebViewВнутри лаунчера — JavaFX WebView, куда грузится удалённый HTML: repo.tlauncher.ru/…/configs_v1/pages/index_ru.html. Страница не входит в поставку — её содержимое определяет сервер.

  5Окно консоли ConsoleSubscriberОтдельное окно лога (позиция и размер хранятся: gui.console.x/y/width/height, gui.console=none). Вывод дочернего процесса дублируется в лог-файл.

  6Масштабирование-Dsun.java2d.uiScale.enabled=false + своё scaling.setting=100 — приложение само управляет масштабом, игнорируя системный DPI.

4.3. Локализация

  Starter: 11 языковых bundle прямо в образе — ru, uk, zh, ro, pl, de, fr, pt, it, es, en. Вытащенный английский bundle — 21 ключ (validate.workdir, validate.size, update.app, upload.error, accept.and.update, …).

  Лаунчер: 48 языков (languages= в конфиге) + таблица converter.value.* — самописный «конвертер» названий языков, где каждый язык подписан сразу в трёх видах: на своём, по-русски и по-английски (напр. converter.value.ru=Русский (Russian)).

  Есть даже забавные баги перевода: converter.value.lo=יידיש (Lao) — лаосскому языку досталась надпись на идише; zh_CN=中国人 («китаец» вместо «китайский»).

4.4. Что видно по стилю

Дизайн — типичный «лаунчер-магазин» 2010-х: Calibri, серый #585858, жёлто-оранжевые акценты, скруглённые кнопки, картинки-офферы, встроенный браузер для промо-страниц. Никакой тёмной темы, никакого следования системным настройкам — это самостоятельный «бренд-интерфейс», а не нативный Windows-диалог.

05 · Фишки и механики

Ниже — то, что реально реализовано (каждый пункт подтверждён классом, строкой или логом).

  1Гонка зеркал DesktopUtil / domainAvailability
  Старт: 11 хостов проверяются параллельно с таймаутом 1500 мс, затем повтор с 4500 мс. Победители сортируются по времени отклика, результат пишется в domainAvailability.json / domainAvailabilityV1.json (available, responseTime). Дальше все запросы идут на самый быстрый.

  2HTTP-кэш с валидацией FileCacheServiceImpl
  Перед скачиванием — HEAD-запрос и сравнение ETag, Last-Modified, sha1, lastAccessAt. Если не изменилось — файл не качается. Кэш разложен по папкам-хостам: cache\https_repo.tlauncher.org\….

  3Проверка целостности HashSumAndSizeError
  У каждого ресурса в конфиге — sha1 + size. При несовпадении — исключение и повтор с другого зеркала. Но хеш берётся из того же JSON, что и сам файл (remoteServerSHA1: false).

  4Двойной self-update
  Сначала starterUpdateV2.json — обновление самого exe, потом appConfig.json — обновление jar'а. exe передаёт jar'у -starterJarFile=…\TLauncher.exe, чтобы тот знал, какой файл ему заменять.

  5Своя JRE на борту javaConfig21.json
  Качает jre-21.0.11-windows-x64.zip (76.7 МБ, sha1 e4d987cc…) с тех же зеркал и распаковывает в starter\jre_default\. Есть варианты для LINUX/x64 и отдельная -utf-8 сборка. Системная Java не нужна.

  6Защита от двойного запуска
  Файл-замок starter\protection.txt + сообщение download.lock.message: «Application is already downloading or a previous instance did not exit cleanly. Close the other process in Task Manager».

  7Пять валидаторов окружения by.gdev.handler
  ValidateWorkDir (права на папку), ValidateTempDir / ValidateTempNull (TEMP не задан), ValidatedPartionSize (свободное место, порог free.partition.size=5), ValidateEnvironment (шрифты), X32Interceptor (32-бит → отказ с ссылкой на сайт).

  8Процесс-менеджер JavaProcessHelper / ProcessMonitor
  Собирает командную строку из JVMConfig, стартует java.exe, читает stdout/stderr, дублирует в лог и в окно консоли, следит за кодом выхода. Отсюда и импорты CreateToolhelp32Snapshot, OpenProcess, TerminateProcess.

  9Офферы с «периодом отказа»
  Offer / PointOffer / InstalledOffer + refusalDelay: после отказа оффер не показывается 2 дня и возвращается. В диалоге — «Accept offer and Update» / «Decline offer and Update».

  10Реклама, управляемая сервером
  ad.tlauncher.org, статус с auth.tlauncher.org/skin/advertising/status, флаги gui.notice.ad_other / ad_server / ad_youtube, список баннеров с сервера, стартовая страница в WebView.

  11Партнёрские серверы с геотаргетингом InnerStateServer-1.3.json

10 · Безопасность и риски

  Plain HTTP зеркало advancedrepository.net в активной цепочке — MITM-поверхность.

  Выгрузка логов на securelogger.net / .top — домены вне бренда; в логах пути пользователя, версии, ники.

  PPI-офферы браузеров, вшитые прямо в диалог обновления.

  Self-update: приложение само заменяет свой exe и свой jar.

  log4j-1.2.17 + самодельные патчи fix_log4j/*.json.

  Привилегированные API в импорте (наличие ≠ использование): AdjustTokenPrivileges, DuplicateTokenEx, AccessCheck, SetSecurityDescriptorOwner/Dacl, SetFileSecurityW, AddAccessAllowedAceEx; плюс CreateToolhelp32Snapshot, Process32First/Next, OpenProcess, TerminateProcess. Обычно это ACL при обновлении и убийство зависших java-процессов, но назначение в этом разборе не подтверждено.

Чего не найдено: упаковщика, шифрования строк, анти-отладки (IsDebuggerPresent, NtQueryInformationProcess не импортируются), инжекций в чужие процессы, драйверов, скрытых сервисов, обфускации control-flow.

13 · Рекомендации

Если лаунчер нужен

  заблокировать телеметрию и логи: securelogger.net, securelogger.top, ruzone.securelogger.top, stat.tlauncher.ru, stat.fastrepo.org, ad.tlauncher.org — лаунчер продолжит работать;

  advancedrepository.net заблокировать обязательно (plain HTTP);

  в настройках выключить статистику, рекламные уведомления и Discord-статус;

  не нажимать «Accept offer and Update»;

  помнить, что %APPDATA%\.tlauncher\starter\ содержит рабочий jar, и он обновляется сам.

Если нужен полный контроль

Не запускать exe: забрать original-TLauncher-2.9xxx.jar и зависимости из dependencies.json
и запускать вручную через свою JRE 21. Тогда starter (self-update, офферы, логирование, реклама) полностью
выпадает из цепочки — остаётся только сам лаунчер.

Если хочется проверить здесь и сейчас

# 1. хеши файлов, которые starter скачал
Get-FileHash "$env:APPDATA\.tlauncher\starter\original-TLauncher-2.9374.jar" -Algorithm SHA1
# 2. сравнить с appConfig.json
Get-Content "$env:APPDATA\.tlauncher\starter\cache\https_repo.tlauncher.org\tlauncher-sources\prod\prerelease\tlauncher\appConfig.json"
